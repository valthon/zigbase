# Changelog

All notable changes to `@zigbase/client` are documented here. The format is based
on [Keep a Changelog](https://keepachangelog.com/), and this package adheres to
[Semantic Versioning](https://semver.org/).

## [Unreleased]

### Security

- **Realtime connections are now de-authed on logout.** Previously, clearing the
  auth store (logout) while a realtime WebSocket was open left the connection
  authenticated server-side — the socket kept delivering events under the
  logged-out identity until it was closed or reconnected. The client now sends an
  empty-token `auth` frame on that transition, which the server rejects and treats
  as a de-auth, clearing the connection's identity while leaving existing
  subscriptions in place. A fresh anonymous connection still sends no auth frame.

### Fixed

- **Realtime: rapid auth changes (e.g. quick login/logout churn) no longer strand
  an in-flight subscribe.** Back-to-back `auth` frames now share a single pending
  ack instead of overwriting its resolver, so a waiting resubscribe always settles
  on the next auth response rather than hanging.

## [0.3.0] - 2026-07-04

Feature-parity release: closes the gap between the client and the server's
search, tenancy, abilities, analytics, senders, and realtime surfaces, and adds
self-service auth management. **Ships with ZigBase server 0.10.0.** Most features
require server ≥ 0.9.0; `senders.list`, cursor-paginated analytics events,
`changePassword`, and per-device session management require ≥ 0.10.0. See the
server 0.10.0 changelog for the coupled wire-format changes.

### Changed

- **BREAKING: the typed where-DSL `in` operator now compiles to the native
  `field in (…)` server filter** instead of desugaring to an `||`-chain. Requires
  ZigBase ≥ 0.9.0 — against an older server a `{ in: [...] }` clause now returns
  a 400 rather than working. No server-version sniffing; the typed tier tracks the
  current server release.
- Clients regenerated by the 0.10.0 code generator require `@zigbase/client` ≥
  0.3.0, enforced by a `CoreSupports_0_3` marker type that fails typecheck with a
  self-explaining error against an older client.

### Added

- **Search.** Full-text `search` and structured `vector` queries (`vectorSpec`,
  `VectorQuery`) on list reads, with per-collection compile-time gating in the
  generated tiers.
- **Multi-tenancy.** Account scoping via the `accountId` option,
  `client.withAccount(id)` scoped views (sharing the auth store), and
  `client.accounts.activate(id)` (`AccountsService`, `AccountScope`).
- **Abilities.** `getAbilities(id)` on the base and every generated collection
  service (`RecordAbilities`).
- **Analytics reads.** `client.analytics.events(...)` and
  `client.analytics.rollup(name, ...)` (`AnalyticsService`, `AnalyticsEvent`,
  `RollupBucket`); cursor pagination on `events` requires server ≥ 0.10.0.
- **Verified senders.** `client.senders.list/create/verify` (`SendersService`,
  `SenderIdentity`); `list` requires server ≥ 0.10.0.
- **Realtime custom topics.** `subscribeTopic`/`unsubscribeTopic` deliver `signal`
  and `message` frames; feature-change notifications arrive via
  `subscribeTopic("__features", cb)`.
- **Self-service password change.** `CollectionService.changePassword(id,
  oldPassword, newPassword)` via `PATCH /records/:id`; transparently
  re-authenticates the current device when the caller changes their own password
  (requires server ≥ 0.10.0).
- **Per-device sessions.** `CollectionService.listSessions()`, `revokeSession(id)`,
  `revokeAllSessions()` against `/auth/sessions[/:sid]` (`SessionInfo`).
  `listSessions`/`revokeSession` require the server to run `.session_store =
  .table`; `revokeAllSessions` works in both session-store modes.
- **Generated-client metadata.** Generated TS clients surface `searchable`/`tenant`
  schema metadata: typed `search`/`vector` options, per-collection sort unions
  (`sort: "-age" | [...]`), tenant fields omitted from `*Create`/`*Update`, and
  `accounts`/`analytics`/`senders`/`withAccount` on the generated client.

### Fixed

- The TypeScript code generator emitted an orphan `Expand` type key (breaking
  `tsc`) for relations targeting a collection outside the generated set; it now
  emits `never` for those relations.
- Realtime: concurrent `subscribe`/`subscribeTopic` calls for the same topic while
  the socket is open no longer send duplicate subscribe frames — later callers join
  the pending ack.

## [0.2.0] - 2026-06-21

Tracks the server's auth overhaul. **Requires ZigBase server ≥ 0.5.0** — the legacy
OAuth2 endpoints this client used to call no longer exist server-side.

### Changed

- **BREAKING: OAuth2 retargeted to the new server contract endpoints.**
  - `authWithOAuth2()` now `POST`s to `/auth/oauth2/complete` (was `/auth-with-oauth2`)
    and resolves to `OAuth2AuthResponse` (`{ token }`) — the response no longer carries
    `record` or `meta`. The endpoint sets the `zb_auth`/`zb_csrf` cookies directly; the
    auth store now saves the token with a `null` record.
  - `oauth2Init()` now `POST`s to `/auth/oauth2/initiate` (was `/oauth2-init`) and resolves
    to `OAuth2InitResponse` (`{ authURL?, clientId?, scopes?, state? }`) instead of `{ state }`.
  - `listAuthProviders()` now `GET`s `/auth/oauth2/providers` (was `/oauth2-providers`).
- **BREAKING: `AuthStore.save(token, record)` widened to accept `record: AuthRecord | null`.**
  OAuth2 login stores a token with no record, so the signature on `AuthStore`,
  `BaseAuthStore`, and `LocalAuthStore` now permits `null`. Custom `AuthStore`
  implementations must update their `save` signature.

### Added

- `OAuth2AuthResponse` and `OAuth2InitResponse` response types.

## [0.1.0] - 2026-06-10

- Initial release of the official TypeScript client: typed records/collections,
  filter/sort/expand query builder, auth store (base + localStorage), password auth,
  and realtime over WebSocket.
