### Fixes

- **Postgres: `.nocase` indexes are now genuinely case-insensitive — closes the PG `.nocase` case-sensitivity caveat (#159).** A comptime index marked `.collation = .nocase` (the documented email-uniqueness pattern the example apps use) used to provision **case-SENSITIVELY** on Postgres, because Postgres has no `COLLATE NOCASE` — so a `.nocase` UNIQUE index silently let `Bob@x.com` and `bob@x.com` both insert as separate identities. It now provisions a `lower("col")` **functional index** (built-in; no `citext`/extension dependency), so a `.nocase` UNIQUE index rejects case-variant duplicates on Postgres exactly as on SQLite. Lookups and comparisons are routed through the same normalization to agree with the index: the auth identity/email lookups (`findByIdentity`/`findByEmail`) and filter/rule equality (`=`/`!=`/`in`) against a `.nocase` column emit `lower("col") = lower($n)` on Postgres so they use the functional index and match its case-insensitive uniqueness. SQLite behavior is unchanged (byte-identical SQL). The previous startup warning for `.nocase` indexes under Postgres is removed.
