### Features

- Pluggable error reporter: the terminal backstop every framework-swallowed error routes through is now a swappable plugin selected via `App(.{ .reporter = MyReporterPlugin })`, mirroring `.storage`/`.mailer`. The default picks `SentryReporter` when `ZIGBASE_SENTRY_DSN` is set (POSTs a Sentry envelope) and `LogReporter` otherwise (logs a structured backstop line `[phase] err_name: message`). A custom plugin implements `create`/`interface`/`deinit` and returns a `Reporter` whose `report` receives a `Report{ .message, .err_name, .phase, .level }`. The `Reporter`, `Report`, `LogReporter`, `SentryReporter`, and `DefaultReporterPlugin` types are re-exported for composition.
- `ctx.reportError(err, "fmt", .{args})` reports a consumer-swallowed-but-notable error through the SAME backstop the framework uses for its own caught errors — the `onError` handler then the reporter (Sentry or the log backstop), with TTL dedup + non-blocking queued delivery — tagged with the new `.app` error phase. It is best-effort and NON-FAILING (it never blocks or fails the caller, and swallows its own allocation failure), and is usable from a route handler, hook, job, or cron.
- Error reports are delivered **non-blocking**: the Sentry POST is enqueued on the in-process memory queue and performed on a pool worker instead of running inline on the thread that swallowed the error, so error reporting never blocks a request/job/cron path and never touches the DB writer. Delivery is best-effort (a failed POST is logged and dropped, never retried into a loop).
- Error-report TTL dedup via `App(.{ .reporter_dedup = .{ .window_s = 60 } })` (the default when omitted): a repeat of the same `(message, phase)` within the window is suppressed, so a hot error path reports once per window instead of flooding Sentry. `.reporter_dedup = .off` reports every swallowed error and compiles the dedup map out entirely.
