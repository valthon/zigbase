### Fixes
- Record before-create, before-update, and before-delete hooks preserve explicit `ctx.fail` 4xx and 5xx statuses supported by the HTTP transport and their messages, and `ctx.invalid` field details. Stack-backed error messages and fields are copied before hooks return; recovered failures cannot leak into later handlers. A supported status without a dedicated code, such as 422, uses `bad_request`. Other hook failures, including unnamed 4xx statuses such as 432, retain the generic 400 response, and rejected writes still roll back atomically. Hook 5xx responses invoke `onError` and the reporter backstop with phase `before_hook`, including allocation-failure fallback responses; each report's message names the collection, status, and hook message.
- Unmapped 4xx statuses use the generic `bad_request` code consistently in typed routes, route `ctx.fail`, and auth-method failures. Auth-method failure messages with a named 4xx status are deliberately client-facing, including 422; these previously became a generic 500 for statuses without dedicated codes. Auth-method 5xx and unnamed-status (such as 432) messages remain operator-only: logged and redacted from client responses.
