### Fixes

- `GET /api/realtime/backfill` no longer answers `500` for every view-narrowed caller (tenant scope, ability or view rule) whose checkpoint spans a retained delete on a collection with a relation field. The delete is now authorized per item: it reaches callers who could view the deleted record, such as its owner, and is skipped for everyone else. Before, the page failed on every retry of the checkpoint until the delete left retention, with the process-local store and the durable journal, on SQLite and PostgreSQL. A deletion snapshot that can never be authorized (a stored value that no longer fits its field, or a rule that cannot be evaluated against it) is now skipped for that caller and logged, so one retained item can no longer block a backfill page; this also stops the matching `realtime: dropped delivery` errors for live delete frames. A transient server failure while authorizing it still answers `500`, so a retry can deliver the delete (#499).
