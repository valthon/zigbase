### Fixes

- A REST record delete, with or without an `Idempotency-Key`, now announces the rows its relation foreign keys change: realtime publishes a `delete` event for every record removed by `cascadeDelete` (transitively), authorized per subscriber against that record's pre-delete state, and an `update` event for every record whose single relation was set to `null`; `-Ddurable-realtime` journals both in the delete's transaction. Previously these rows changed silently and subscribers and replay stayed stale. The rows are read from the database's own foreign keys; TTL-expired rows are not announced. Announcing never fails the delete: above 1000 affected records (each counted once), for a foreign key the engine cannot map to a row id (a composite or alternate-key reference from a migration), or for a cascaded row that cannot be decoded or whose snapshot is too large to journal, the delete degrades to backfill invalidation and a journal reset (`resetRequired`). Record hooks do not run for these rows. Deletes through the `Data` facade, raw SQL, migrations and TTL expiry still cascade without announcements. (#489)
