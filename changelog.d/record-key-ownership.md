### Fixes
- Fixed a long-standing memory leak in the `Data` facade: `findById`/`create`/`update`/`delete`/`list` loaded the collection metadata via `collections.get` and never freed it, leaking on every call when driven by a general-purpose (non-request-arena) allocator. Record `Value`s now own their top-level keys, so the facade can free the collection safely.
- Fixed a cursor-mode `records.list` result that returned a capacity-padded item slice and left the pagination probe row unfreed — harmless under a request arena but a wrong-size free / leak on a non-arena allocator. The result is now an exact-length owned slice with a `deinit`.

### Internal
- Record `Value`s returned by `get`/`create`/`update` now own their top-level keys (self-contained), while `records.list` interns one shared key set per query (borrowed by every row, freed once via the new `ListResult.deinit`) so the list read path adds no per-row key allocation. `records.freeRecord` frees a self-contained record on any allocator. On the back of this (plus `Collection.deinit`), the realtime-hub delivery tests and the `Data`-facade engine tests drop their arena masking and run under the raw leak detector. The hub tests that also exercise the query-guard path (`policy.matchesRule`) and the facade `list` tests stay arena-scoped — that scratch is owned by the not-yet-migrated `policy.zig`/`rules.zig`/`query/` subsystems (separate follow-ons) — with their allowlist justifications corrected to say so.
