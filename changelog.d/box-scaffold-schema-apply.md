### Changed
- `zigbase init --box` now scaffolds `schema/collections.json` as a `{"zigbaseSchema": 1, "collections": [...]}` document for `zigbase schema apply`, replacing the bespoke bare-array format and the `scripts/apply-schema.sh` curl/jq script it required (an auth dance the operator had to script by hand). `schema apply` is idempotent (re-applying an already-applied document reports `applied: []`), needs no superuser session token, and is the same declarative-schema surface `docs/migration-tools.md` already documents -- one schema-file format for the concept, not two. `docker-compose.yml` gains a read-only `./schema:/schema:ro` bind mount so `docker compose exec zigbase /zigbase schema apply /schema/collections.json` works out of the box; a read-only bind of a plain file needs no chown dance. If a server is already running against the data dir (SQLite, non-frozen), restart it after applying -- its in-process collection cache has no TTL and isn't invalidated by a separate `schema apply` process, so it can keep serving stale or not-found metadata until it restarts; see `docs/migration-tools.md` §2/§7 for the full mechanism. AGENTS.md's box-mode Trap 7 and layout/commands tables, `zigbase init`'s usage text, and `site/src/content/docs/configuration.md` are updated to match.
