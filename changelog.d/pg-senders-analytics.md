### Fixes

- On PostgreSQL, `GET`/`POST /api/senders`, `POST /api/senders/:id/verify`, `GET /api/analytics/events` and `GET /api/analytics/rollups/:name` no longer answer 500. Their queries now use PostgreSQL placeholders and time functions, and a rollup that has not run yet returns an empty `items` list, as it does on SQLite. Event and rollup ordering and the `since`/`from`/`to` filters compare text byte by byte, as on SQLite, whatever the database's locale, and the existing `_events` indexes serve that order. On upgrade, a PostgreSQL-only migration (`0030_analytics_text_collation`) resolves `_events` and existing `_rollup_*` tables through `search_path` (including legacy tables in later schemas) and gives their text columns the `"C"` collation; it locks those tables and rebuilds their indexes while it runs (1.1 s measured for 400,000 events).
