### Internal

- Made the SQLite full-text-search provisioning and query-building paths self-freeing (allocator ownership contract 1). `fts.ensureIndexSqliteImpl` (the FTS5 external-content table + sync-trigger provisioning run per searchable collection at startup) built its ~two-dozen DDL/probe scratch strings on the caller's allocator and never freed them; it now builds them on a function-local arena. `fts.build` leaked its internal table-name scratch (`ft` on SQLite, `tsv` on Postgres) — copied into the returned SQL fragments but never freed — which is now freed, while the escaping strings (and the aliased Postgres query `term`) stay on the caller allocator. As with the other contract migrations this is correctness, not a runtime change: both production callers (`provision.applySpecs`, `records.list`) already pass an arena that reclaimed the scratch, so the fix removes a latent leak for a non-arena caller and lets the two `search/fts.zig` tests (`sanitize`, and the `ensureIndex` provisioning/trigger integration test) run under the raw leak detector. The `fts.zig` allocator-contract allowlist entry is removed (2→0).
