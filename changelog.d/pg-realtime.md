### Internal

- PostgreSQL backend, realtime parity + cross-instance fan-out (#159, PR-6/PR-6b): made the realtime change-feed work on Postgres and, crucially, **across app instances** sharing one database. The change-feed itself was already backend-agnostic (after-commit dispatch → facil.io in-process pub/sub; no `update_hook`/triggers/WAL polling), and the per-subscriber delivery authz (`realtime/hub.zig` `shouldDeliver` → `policy.matchesRule`) already composes the view/ability/tenant predicates through the dialect, so create/update delivery authorizes against the live row with Postgres-correct `$n`/`now()` SQL unchanged. The one historically SQLite-coupled spot — the **delete-snapshot** authz sandbox (`hub.matchesSnapshot`, which evaluates an owner/expression-scoped `viewRule` against the deleted row's snapshot in a throwaway in-memory DB) — needs no `:memory:` Postgres analog: `db.Db.openMemory()` is **always** the SQLite union arm (SQLite is compiled into every build), so the snapshot sandbox is a self-contained SQLite-dialect rule evaluator that never touches the live DB and works identically whichever backend is live. Documented + pinned with live-PG tests.
- Cross-instance delivery via Postgres **LISTEN/NOTIFY** (`src/realtime/pg_bridge.zig`): on the same after-commit dispatch, the writer additionally issues `NOTIFY zigbase_rt, '<payload>'` carrying a **minimal** `{origin, collection, action, id}` body (plus, for deletes, the pre-delete snapshot so remote instances can authorize the gone row — dropped if it would exceed NOTIFY's 8000-byte limit, in which case remotes conservatively deny owner-scoped deletes). Every process runs **one dedicated listener connection** (`startRemoteListener`, spawned just before `zap.start`) that consumes notifications and re-feeds the EXISTING in-process hub: create/update re-fetch the live row, delete uses the carried snapshot, then `WS.publish` runs each local subscriber's unchanged `onChannelMessage` authz. A per-process **origin id** tags every NOTIFY so the listener skips its own writes (the writing instance already delivered in-process — no double delivery). Logical decoding was rejected as operationally heavy and authz-bypassing overkill given the clean after-commit hook.
- **Gated cleanly:** NOTIFY/LISTEN only fire when the active backend is Postgres (self-gated via `db.poolBackend`); the new `db.Db` seam helpers (`dbListen`/`dbNotify`/`dbWaitNotification`) are comptime no-ops on SQLite. SQLite stays single-process and **byte-identical** — the in-process `broadcast` path is behavior-unchanged (refactored only to share a `publishFrames` core with the listener), confirmed by the existing realtime browser suite.
- Live cross-backend tests (`src/backend/postgres/realtime_pg_test.zig`, `-Dpostgres=true`, skip when no PG): owner-scoped + `@public` + locked create/update/delete delivery authz on a real Postgres collection, the delete-snapshot path with the row absent from PG, and the cross-instance path proper — a change `NOTIFY`'d on connection A is received + decoded by a `LISTEN`er on connection B (two instances, one database) and authorized for B's would-be subscribers (incl. the delete snapshot ride-along). Plus codec unit tests (`pg_bridge.zig`) covering encode/decode round-trips, the oversize-snapshot drop, and origin-id stability (these run in the default build too).
