### Security
- Verify existing auth identity indexes before trusting them, on SQLite and PostgreSQL. A same-name object that is not the engine's unique non-empty index on that identity field no longer stands in for identity uniqueness: collection create/update, superuser auth-options updates, rename, database import (including existing tables under `migrate-db --force`) and startup refuse it, or a temporary table or index shadowing the collection or index name, and leave it unmodified. The diagnostic naming the collection, field and index is the REST 400 body for create/update; rename reports a plain conflict, and every path logs it. Startup also restores a missing identity index. On SQLite only a narrow predicate spelling is recognised, and a field name SQLite reads as a keyword or literal (such as `null`) must be quoted in it (see KNOWN_LIMITATIONS.md), so a logically equivalent index may be refused. On SQLite the identity column itself must keep the default BINARY collation: a column a migration declared `COLLATE NOCASE` (or RTRIM, or a custom collation) is refused, because login compares with the column's collation while the identity index enforces BINARY uniqueness, so `Alice@x.io` and `alice@x.io` could both exist and both match. For case-insensitive identities, declare a `.nocase` unique index instead. Removing a field from `identityFields` leaves a migration's object under its old index name in place and does not refuse; a new or changed index declared under that name (such as making it unique) is refused (REST 400 or startup refusal) with a diagnostic naming the collection and index unless the preserved object already matches it, so a new or changed declaration is never recorded over an object that does not enforce it.

### Fixes
- Declared-index lookups on SQLite ignore same-name triggers. PostgreSQL: declared indexes are looked up, dropped and recreated in the collection table's own schema, so a same-name index in an earlier `search_path` schema is no longer mistaken for the collection's or dropped by an update; names over 63 bytes are matched by their truncated catalog name. SQLite provisioning does the same in `main`, leaving temporary same-name indexes alone.
