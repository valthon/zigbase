# Site: tabbed Admin-UI / Terminal tutorial + capability showcase

**Date:** 2026-06-10
**Status:** Executed autonomously (user away); review via PR.

## Problem

The site tutorial predates the admin SPA and the example frontends. It walks the
reader through everything with `curl`, never shows the admin UI, and the examples
pages have no screenshots of their frontends. The site under-sells what ZigBase
ships out of the box.

## Goals

1. Every tutorial step that can be done two ways (REST/curl vs the embedded admin
   UI at `/_/`) presents **both paths in a tabbed block**; switching one block
   switches **all blocks on the page** (the page only ever shows one path).
2. Real screenshots of the admin UI at each tutorial step, and of the three
   example frontends (blog, golfsim, plugins), reproducibly generated by script.
3. The marketing site visibly demonstrates all major capabilities: collections &
   schema editor, access rules, auth, file uploads, realtime, OAuth2 config,
   static file serving, the Zig framework, and the example apps.

## Design

### 1. `PathTabs.astro` — page-wide synced instruction tabs

New component in `site/src/components/`:

- Two fixed panels: `ui` → label **"Admin UI"** (default), `cli` → label
  **"Terminal (curl)"**. Fixed ids keep all instances in lockstep.
- Same ARIA tabs pattern as `CodeTabs.astro` (roles, arrow-key nav), but
  selection is **global**: clicking a tab dispatches a
  `zb:pathtabs` CustomEvent on `document`; every instance listens and updates.
  Choice persists in `localStorage('zb-path')` so it sticks across pages and
  visits.
- Visually distinguished from CodeTabs (pill-style switcher with a small
  "applies to the whole page" hint on hover/title) so readers understand the
  global behavior.
- **Rule: headings (h2/h3) never go inside tabs** — the TOC links to headings,
  and hidden panels would break anchor scrolling. Tabs wrap step bodies only.

### 2. MDX

- Add `@astrojs/mdx`; extend content globs to `**/*.{md,mdx}`.
- Convert `docs/tutorial.md` → `tutorial.mdx`, `docs/quick-start.md` →
  `quick-start.mdx`, and the three `examples/*.md` → `.mdx` (they need
  `Browser` + `Image` for framed screenshots).
- `render(entry)` API, rehype heading/anchor plugins, sidebar, and TOC all keep
  working (verified against Astro 5 MDX docs; headings extraction is unchanged
  for markdown-style headings, which stay outside components).

### 3. Screenshot pipeline

### 4. Tutorial rewrite (`tutorial.mdx`)

Same golfsim narrative, restructured:

- **Step 0 (run the server):** terminal-only (no tabs) + "open the admin UI"
  with the login screenshot.
- **Step 1 (provision collections):** tabbed. *Admin UI:* create `users`
  (auth), `simulators`, `listings` in the schema editor — relation targets are
  picked by **name** from a dropdown, so no id-capturing; screenshots at each
  stage. *Terminal:* the existing curl flow with id capture.
- **Step 2 (access rules):** tabbed. *Admin UI:* API Rules tab, lock toggle =
  superuser-only (`null`), empty = public, expression otherwise; screenshot.
  *Terminal:* rules as JSON in the create payloads (already set in step 1).
- **Honesty callout:** advanced field options (`cascadeDelete`, number
  `scale`/`min`, text `min`/`max`, `mimeTypes`) are API-only today; the UI
  path creates the same schema minus those constraints and the callout says so.
- **Step 3 (register + log in a user):** tabbed. Signup/login is an end-user
  API action in both paths (the admin record drawer intentionally has no
  password field); the *Admin UI* tab runs the same two curls, then verifies
  the new user in the `users` records table (screenshot) and notes the table
  is **live** — a realtime subscriber.
- **Step 4 (records + file upload):** tabbed. *Admin UI:* "+ New record"
  drawer, relation dropdown, file input; screenshots. *Terminal:* existing
  curl `-F` multipart flow.
- **Steps 5–7 (Zig route/job/App):** unchanged (Zig-only, no tabs).
- **New closer:** "the finished app" — golfsim frontend screenshot in a
  `Browser` frame, linking to the example (and the other examples).

### 5. Quick start (`quick-start.mdx`)

Stays terminal-first (it's about running a binary); the "Open the admin UI"
section gains the login screenshot and a pointer to the tutorial's dual paths.

### 6. Examples + landing

- Each example page gets its frontend screenshot(s) in a `Browser` frame near
  the top, plus the existing prose.
- Examples index cards get screenshot thumbnails.
- Landing gets a new **"See it built"/examples showcase** section (three framed
  shots linking to the example pages), and `AdminShowcase` copy is extended to
  mention rules/OAuth2/realtime live table.

## Alternatives considered

- **Raw-HTML tabs in .md (no MDX):** markdown inside block HTML loses Shiki
  highlighting and list rendering — rejected.
- **Per-block independent tabs (reuse CodeTabs):** violates the "page shows one
  path" requirement — rejected.
- **URL-param sync (`?path=ui`):** survives sharing but forces link rewriting
  and reload semantics; localStorage + event bus is simpler and sticks across
  pages — chosen.

## Testing

- `npm run build` + `npm run check` clean.
- Built pages eyeballed via Playwright screenshots (tabs render, switching one
  switches all, both paths complete, images load, TOC anchors work).
- Screenshot script is idempotent and committed for future regeneration.
