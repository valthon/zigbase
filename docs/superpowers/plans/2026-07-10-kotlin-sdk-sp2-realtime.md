# Kotlin Client SDK KSP2 (Realtime Tier) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the realtime (WebSocket) tier of the Kotlin SDK: `ZigbaseClient.realtime` — ack-gated subscriptions over the server's frame protocol with the full auth lifecycle, reconnect/backoff, `Flow`-based streaming, and custom broadcast topics — coroutines-native over ktor's WebSocket client.

**Architecture:** One `RealtimeService` in `clients/kotlin/src/main/kotlin/io/github/valthon/zigbase/realtime/Realtime.kt`, porting the Python SP2 state machine (the most-hardened realtime implementation: every SP2 review lesson is baked into its current shape) onto structured concurrency: an injectable suspend connector (the Dart/Python pattern), a receive-loop coroutine per connection, `CompletableDeferred` acks, `Mutex`-guarded connect state, and `Flow` streaming built on the consumer's own collection context (no background tasks per stream). Ktor's `HttpClient(CIO) { install(WebSockets) }` is the default connector.

**Tech Stack:** existing KSP1 toolchain (Kotlin 2.4, ktor 3.5 incl. `ktor-client-websockets`, kotlinx-coroutines, JUnit5 + coroutines-test); fake in-memory connector for unit tests; live server binary for integration.

**Normative references:** `clients/python/src/zigbase/realtime.py` is THE reference — it carries every hardening from SP2's five review rounds (drop-settles-auth-gate, cancel-mid-connect flag reset via try/finally with BaseException discipline, reconnect gated on live subscriptions, fire-and-forget send guards, error-frame entry deletion, r:/t: key scheme, reused-detached auth-ack). `clients/typescript/src/realtime.ts` is wire truth. The server protocol facts (from SP2 research, unchanged): WS `/api/realtime`, no token in URL, no Origin needed; uplink `auth`/`subscribe`(filter omitted when null)/`unsubscribe`; downlink `connect`/`auth`(ok|error)/`ack`/`error`/`event`(delete=id-only)/`signal`/`message`; silent token expiry (client re-auths on store change); backpressure = server disconnect; 256-sub cap; reconnect = re-auth → resubscribe → re-fetch (no replay). The design spec is `docs/superpowers/specs/2026-07-10-kotlin-sdk-design.md` (KSP2 section).

## Global Constraints

- All KSP1 conventions hold (gates `mise exec gradle@9.6 -- gradle -p clients/kotlin spotlessCheck build`, TDD, KDoc counterparts, Spotless, internal visibility for internals, commit style + trailers).
- **Structured-concurrency ownership decision (spec deferred it — DECIDED here):** the client owns the scope. `RealtimeService` creates its own `CoroutineScope(SupervisorJob() + Dispatchers.Default + CoroutineName("zigbase-realtime"))`; `close()` cancels it. Consumers never supply a scope; `subscribe` returns a suspend unsubscribe lambda; `stream()` returns a cold `Flow` that does its work in the collector's context (no service-scope tasks per stream). Document this explicitly — it is the Kotlin-specific divergence the spec demanded be explicit.
- Frame parity byte-for-byte with Python's codec (filter key OMITTED when null; malformed downlink dropped silently).
- The hardened state-machine contract (every item was an SP2 review finding — day-one requirements): ensure-connected no-ops on connected/connecting/reconnect-pending; connect-flag reset on ALL exits incl. cancellation (try/finally; CancellationException propagates after cleanup); auth-first open gating resubscribe on the reply SETTLING (ok or error — public subs proceed); reused auth-ack `CompletableDeferred` detached before settling; receive-loop finally settles the auth gate AND leaves pending subscribes for reconnect re-send; reconnect backoff 250ms→10s doubling (shift-capped), attempts reset on open, gated on LIVE SUBSCRIPTIONS at schedule time, throwing delay/connect never wedges the pending flag; error frames reject unacked pending + DELETE entries (reconnect never resurrects rejected topics); fire-and-forget sends guarded (send failures → onError + converge through drop handling, never escape to callers); r:/t: prefix keys (the `subscribe("", filter="topic:x")` collision regression test); one frame per key with concurrent subscribers sharing the ack; unsubscribe frame only on last-variant removal; empty-token de-auth on logout via the 2-arg onChange (token used verbatim); onError default = a `java.util.logging`/slf4j-free println? NO — use `System.Logger` (JDK platform logging, zero deps) named "io.github.valthon.zigbase.realtime"; close() idempotent, cancels scope, detaches the store listener, rejects post-close subscribes (status-0), never hangs.
- Known-limitation parity (document, do NOT fix divergently): a pending subscribe whose entry is removed while another still-pending subscribe to the same topic/filter awaits its ack never settles; serialized-dispatch re-entrancy deadlock (an awaited callback subscribing to a not-yet-acked topic); cancelled subscribe leaves its callback registered until unsubscribed.
- Wire lifecycle woven into ZigbaseClient: `val realtime: RealtimeService` lazy; `close()` closes realtime first (needs the scope) then the transport; `withAccount` siblings get their OWN realtime service.
- Integration harness lesson: any JVM-side raw HTTP in tests pins HTTP/1.1 (the h2c-vs-facil.io-400 finding); the realtime connector itself is ktor (fine).
- Commits `feat(kotlin-sdk)`/`test(kotlin-sdk)` etc. with the Claude trailer. Do NOT push (story rebuild precedes any push).
