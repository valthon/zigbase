Open-source backend in a single binary. SQLite to start. Postgres when you grow. Same code.

Collections and access rules, auth from passwords to passkeys, realtime, full-text search, multi-tenancy, background jobs, transactional email, and an embedded admin UI — one executable, no runtime dependencies. Flip one build flag and the same app runs on PostgreSQL. And it's an embeddable Zig framework: extend the server with comptime hooks, routes, and jobs, checked at compile time.

Features

SQLite or PostgreSQL

Embedded SQLite by default. Build with -Dpostgres and point ZIGBASE_DB_URL at a postgres:// URL — same app, same API. zigbase migrate-db copies an existing instance across, schema and data.

Built for coding agents

Scaffold a project with npx zigbase init — a generated AGENTS.md included. serve backgrounds itself when it detects an agent shell, the CLI speaks --json, error codes are a frozen registry you can look up with zigbase explain-code, and any instance answers GET /api/meta.

Migrate an existing app

Declarative schema dump/apply, whole-dataset import --manifest that loads in relation order, and --legacy-hashes bcrypt so existing users keep their passwords — transparently rehashed to argon2id on first login. A parity-replay harness proves the cutover before you make it.

Collections & schema

Typed fields with validation; schema migrations run on startup.

Multi-tenancy

Account-scoped collections: every read, write, and realtime delivery is bound to the request's active account, fail-closed. Built-in accounts, memberships, invitations, and roles.

Relationship abilities

Authorize by the caller's relationship to the row — .{ .via = "account", .min_role = .editor } — comptime-validated, fail-closed, and composed into list queries.

Full-text & vector search

Mark a field .searchable and query ?search= with ranked results — AND/OR/NOT/prefix operators on SQLite (FTS5); ranked tsvector search on Postgres. Opt-in -Dvector adds KNN via sqlite-vec / pgvector.

Background jobs & webhooks

Durable or in-memory queues with priorities and retries; enqueue from anywhere with ctx.enqueue(). ctx.webhook() delivers signed, idempotent webhooks with capped backoff.

Transactional email

Multipart HTML+text templates, SES / Postmark / SMTP providers, verified per-account senders, bounce suppression — and a capture mailer for asserting mail in tests.

Product analytics

ctx.track() appends immutable events — actor, tenant, and timestamp stamped server-side. Declarative rollups aggregate them on the scheduler; tenant-scoped read API.

Realtime

Subscribe to record changes over WebSocket + SSE, and broadcast on custom channels from routes and jobs. On Postgres, record changes fan out across app instances via LISTEN/NOTIFY.

Auth + OAuth2

argon2id passwords, magic-link, OTP, and WebAuthn passkeys; OAuth2 with PKCE and account linking. Hook beforeAuthSuccess and .auth.beforeRegister transactionally with login and registration.

File storage

Local (pluggable) file storage with short-lived file-access tokens.

Single static binary

One executable, no runtime dependencies — the Postgres driver is pure Zig (no libpq, no OpenSSL).

Embeddable Zig framework

Comptime hooks, custom routes, scheduled jobs, and plugins.

Static file serving

Ship your frontend from the same binary — point a flag at a folder, or embed it at compile time.

Typed client SDKs

Official TypeScript, Dart, Python, and Kotlin SDKs. Generate a fully-typed client from your Zig schema — records, realtime, files, and typed custom-route RPC. No Zig source? Bootstrap types from any running instance with npx @zigbase/typegen.

Session management

Revoke all sessions instantly via epoch rotation. Optional per-device session table: list active sessions, revoke one device, or log out everywhere.

Rate limiting & CAPTCHA

Global rate limiter plus per-auth-method limits — set each method's .rate_limit option at comptime, or call ac.rateLimit() from a custom auth method at runtime. And ctx.verifyCaptcha() for reCAPTCHA, hCaptcha, and Turnstile.

Field encryption

Mark any text/JSON field encrypted for transparent AES-256-GCM at rest. Rotate keys with zigbase rewrap — old generations stay readable while you re-encrypt.

TTL & KV store

Auto-expiring records via .ttl_field (GC'd every 5 min). Built-in KV store for feature flags and settings, surfaced in the admin UI.

Ctx capability layer

A single *Ctx handed to every hook, route, and job — wraps records, auth, KV, flags, outbound HTTP, and atomic transactions. One handle for your app's capabilities — pooled DB access, track, enqueue, mail, webhook — no globals.

Deterministic testing

Freeze time with ZIGBASE_FAKE_NOW, fix randomness with ZIGBASE_FAKE_SEED, and capture outbound mail in test suites — all gated off in production builds.

One backend, two ways in

Extend the server in typed Zig, or talk to it over a plain REST API — the same collections, the same access rules, on SQLite or Postgres. 

const std = @import("std");
const zigbase = @import("zigbase");

// Derive a URL slug from the post title before it is created.
fn slugify(ctx: *zigbase.Ctx, ev: *zigbase.RecordEvent) anyerror!void {
    _ = ctx;
    if (ev.record.* != .object) return;
    if (ev.record.object.get("slug") != null) return;
    const title = if (ev.record.object.get("title")) |t| switch (t) {
        .string => |s| s,
        else => return,
    } else return;

    // Mutations MUST allocate with ev.arena.a (owns ev.record).
    const buf = try ev.arena.a.alloc(u8, title.len);
    var len: usize = 0;
    var in_run = false;
    for (title) |ch| {
        if (std.ascii.isAlphanumeric(ch)) {
            buf[len] = std.ascii.toLower(ch);
            len += 1;
            in_run = true;
        } else if (in_run) {
            buf[len] = '-';
            len += 1;
            in_run = false;
        }
    }
    if (len > 0 and buf[len - 1] == '-') len -= 1;
    try ev.record.object.put(ev.arena.a, "slug", .{ .string = buf[0..len] });
}

pub fn main(init: std.process.Init) !void {
    return zigbase.App(.{
        .hooks = .{ .posts = .{ .beforeCreate = slugify } },
    }).runCli(init);
}
fn onSignup(ctx: *zigbase.Ctx, ev: *zigbase.RecordEvent) anyerror!void {
    _ = ev;
    // Immutable analytics event — actor, tenant, timestamp stamped server-side.
    try ctx.track("user.signup", .{ .plan = "free" });

    // Welcome email via the durable "emails" queue (SES/Postmark/SMTP behind one vtable).
    try ctx.mail().enqueue(.{
        .to = "user@example.com",
        .subject = "Welcome!",
        .html = "<h1>You're in.</h1>",
    }, .{ .queue = "emails" });

    // Signed outbound webhook with retry/backoff and an idempotency key.
    try ctx.webhook("https://hooks.example.com/zigbase", .{ .event = "signup" }, .{});
}

Start on SQLite. Grow to Postgres. Change nothing.

The default deployment is one file on embedded SQLite — easy to run, easy to back up. When one box isn't enough, the same application runs on PostgreSQL: opt in at build time, point at a URL, and move your data with one command.

  1. 1

    Ship day one

    ./zigbase serve   # embedded SQLite, WAL, one file
  2. 2

    Opt in to Postgres

    zig build -Dpostgres=true
export ZIGBASE_DB_URL="postgres://…?sslmode=require"
  3. 3

    Move your data

    zigbase migrate-db --from ./data.db --to "postgres://…"

Quick start

Scaffold with npx, grab a binary, build from source, or embed it as a library.

# Scaffold a project — docker-compose, a schema document, AGENTS.md.
# No Zig toolchain, no install step.
npx zigbase init

# Or just run the server (fetches the prebuilt binary for your platform)
npx zigbase serve --insecure-cookies --data-dir ./zb_data
# open http://127.0.0.1:8090/_/  (admin UI)
# Download the prebuilt Linux binary
curl -L https://github.com/valthon/zigbase/releases/download/v0.13.0/zigbase-0.13.0-x86_64-linux-musl.tar.gz | tar xz

# Create a superuser, then serve
./zigbase superuser create --email you@example.com --password "<a strong password>" --data-dir ./zb_data
# --insecure-cookies: local dev is plain HTTP, and auth cookies are Secure by default.
./zigbase serve --insecure-cookies --data-dir ./zb_data
# open http://127.0.0.1:8090/_/  (admin UI) — a JWT secret is generated under ./zb_data
mise install          # installs Zig 0.16.0 (pinned in mise.toml)
zig build             # -> zig-out/bin/zigbase

./zig-out/bin/zigbase superuser create --email you@example.com --password "<a strong password>" --data-dir ./zb_data
./zig-out/bin/zigbase serve --insecure-cookies --data-dir ./zb_data
# curl http://127.0.0.1:8090/api/health   ->  {"status":"ok"}
zig fetch --save git+https://github.com/valthon/zigbase
// build.zig — one call adds the import and wires libc
const zigbase = @import("zigbase");
const zb = b.dependency("zigbase", .{ .target = target, .optimize = optimize });
zigbase.addTo(zb, exe_mod);
// src/main.zig

    return zigbase.App(.{
        .hooks = .{ .posts = .{ .beforeCreate = slugify } },

}

A TypeScript SDK in three forms

From a zero-config dynamic client to a fully-typed client generated from your schema — at build time, or from any running instance with no Zig toolchain.

Base — dynamic

Zero-config client for any ZigBase server. You bring the types.

npm install @zigbase/client
import { createClient } from "@zigbase/client";

const zb = createClient("http://localhost:8090");
const posts = await zb
  .collection("posts")
  .getList(1, 20, { filter: "status = 'published'" });

Comptime — generated

A fully-typed client generated from your Zig schema at build time — typed records and typed custom-route RPC.

zig build gen-client
import { createClient } from "./zbase.gen.js";

const zb = createClient("http://localhost:8090");
const post = await zb.db.posts.create({
  title: "Hello", status: "published",
});
const res = await zb.rpc.bookingsConfirm({ id });

Runtime — introspection

Why ZigBase

An architecture built for simple operation and deep extensibility.

One static binary

A single statically-linked executable with no runtime dependencies — copy it to a server and run it.

An agent can drive it end-to-end

zigbase init scaffolds a project (with a generated AGENTS.md), serve backgrounds itself when it detects an agent environment and reports readiness, the CLI emits machine-readable --json, and every error carries a frozen code an agent can look up with zigbase explain-code. A coding agent can build, run, and debug a backend without waiting on a human.

Embedded database, real database

All data in one SQLite file with WAL by default — easy to back up, easy to reason about. The same code runs on PostgreSQL (opt-in) when you outgrow one box.

A scale path, not a rewrite

zigbase migrate-db moves an existing SQLite instance to Postgres — schema and data, ids and timestamps preserved, encrypted-field envelopes byte-for-byte.

Bring your existing app

Apply a declarative schema document, load a whole dataset with import --manifest (relation order handled for you, cycles included), and carry users across with their existing bcrypt passwords — rehashed to argon2id the first time each one logs in. A parity-replay harness records your old backend and diffs the new one, so you prove the cutover instead of hoping.

Comptime framework

Extend the server in typed Zig with hooks, routes, and jobs — zero-cost abstractions, checked at compile time.

Tiny footprint

Comptime pool levers let you tune memory use down for small deployments — no GC, no VM.

Safe by default

Blank access rules lock a collection (superusers only); only the explicit "@public" sentinel opens it. Rate limiting, field encryption, and CSRF protection are on by default. Tenancy, abilities, and search scoping are fail-closed — a misconfiguration denies, never leaks.

Full auth stack

Password, magic-link, OTP, and WebAuthn passkeys out of the box. Session revocation, auth lifecycle hooks, and per-device session management included.

Deterministic testing

Freeze time, fix randomness, and capture outbound mail in test suites — all via env-var seams gated off in production builds.
