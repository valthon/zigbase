Use the hardware you have.
Measure your next move.

Start with one process and embedded SQLite. Tune readers, workers, and cache settings against your own workload. When you need application replicas, rehearse a move to the opt-in Postgres backend.

Keep your collection API while reviewing database-specific SQL, shared files, and job coordination. Scaling is an engineering decision, with tools to help you make it.

Performance you can investigate

  • Inspect: report effective resource settings.
  • Compare: use zigbase tune with measured throughput, p95 latency, and peak RSS.
  • Track: gate binary size and instrumented allocations with performance contracts.

Component settings are not a process-memory ceiling. Timing trends are advisory; capacity depends on your application and deployment.
